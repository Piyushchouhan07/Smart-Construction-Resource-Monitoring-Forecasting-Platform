# 🏗️ Smart Construction Resource Monitoring & Forecasting Platform (BIM–IoT–ML)

An AI-powered construction management pipeline that integrates **Building Information Modeling (BIM)**,
**IoT data simulation**, **Machine Learning**, and a **Streamlit dashboard** to forecast construction
resource demand and support proactive project planning.

---

## 📌 Project Overview

Construction projects frequently experience delays, cost overruns, and inefficient resource allocation
due to fragmented monitoring systems and a lack of predictive insight.

This project combines:

- 🏢 BIM (Autodesk Revit) quantity takeoffs
- 📡 Simulated IoT site data (labor, weather, logistics)
- 🤖 Machine learning (Random Forest, XGBoost, LightGBM)
- 📊 An interactive Streamlit dashboard

to predict the next **7 days of concrete demand**, enabling smarter decisions and more efficient
resource management.

---

## 🚀 Features

- ✅ BIM-based quantity extraction from Autodesk Revit exports
- ✅ Synthetic IoT data generation (configurable simulation length, default 150 days/zone)
- ✅ ML-based resource forecasting with Random Forest, XGBoost, and LightGBM
- ✅ Automatic model comparison and best-model selection (by R²)
- ✅ Interactive Streamlit dashboard — upload your own Revit CSV and get live results
- ✅ 7-day concrete demand forecast, per zone and total
- ✅ Construction KPI visualization (usage, CO₂, shortage-risk days)
- ✅ CO₂ emission estimation
- ✅ Labor and weather impact modeling

## ▶️ Getting Started

```bash
git clone <this-repo-url>
cd smart-resource-forecasting
python -m venv .venv && source .venv/bin/activate   # optional but recommended
pip install -r requirements.txt
```

### Option A — Run the dashboard directly (recommended)

```bash
streamlit run app/app.py
```

Then upload `data/Revit_Data.csv` (or your own Revit export) in the browser. The app simulates the
IoT data, trains and compares all three models, and shows KPIs, a what-if predictor, and a 7-day
forecast — no notebooks required.

### Option B — Walk through the notebooks

```bash
jupyter notebook notebooks/01_IOT_Simulation.ipynb   # generates data/IoT_Simulation_Output.csv
jupyter notebook notebooks/02_ML_Training.ipynb       # trains models, saves models/best_model.pkl
```

## 📈 Machine Learning Models

The project compares three ensemble learning algorithms on the simulated IoT dataset:

| Model | Speed | Typical Fit | Notes |
|--------|-------|----------|------------------|
| Random Forest | Medium | Strong baseline | Robust, low overfitting risk |
| XGBoost | Slower | Very strong | Handles this dataset's structure well |
| LightGBM | Fastest | Strong | Fastest to train; can underfit on very small datasets |

The pipeline automatically selects whichever model scores the highest R² on the held-out test
set for that run — with the default sample data (450 rows across 3 zones), that's usually XGBoost
or Random Forest.

## 📊 Input Features

- Zone
- Labor Count
- Weather (rain / no rain)
- Truck travel time
- Concrete quality (GOOD / WARNING / REJECTED, derived from travel time)
- Date-derived features (day, month, weekday)

## 📈 Output

- Daily concrete usage prediction
- Next-7-day concrete demand forecast (per zone and total)
- CO₂ emissions
- Shortage-risk flag (once cumulative usage passes 95% of a zone's material budget)

## ⚠️ Known Limitations

- The IoT data is **simulated**, not sourced from real sensors — see "Future Scope" below.
- `data/legacy_training_sample.csv` uses an older column schema (`Zone_ID`, `Active_Machines`,
  `Weather`) that predates the current simulation output and is **not** used by the current
  pipeline. It's kept only as a historical reference; the pipeline trains on
  `data/IoT_Simulation_Output.csv`, generated fresh from `Revit_Data.csv`.
- With only 3 Revit rows / 450 simulated rows in the sample data, R² scores look artificially
  high — the models are fitting a fairly simple simulated process, not real-world noise.
